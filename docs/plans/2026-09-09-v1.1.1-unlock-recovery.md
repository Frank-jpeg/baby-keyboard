# v1.1.1：修复 Esc 退出被残留状态阻塞

## 问题与复现

用户反馈长时间乱按后，Esc 有字符反馈，但长按不开始退出。旧状态机要求每个按下都收到身份完全一致的松开，所有其他输入归零后才允许 Esc 计时。

使用相同输入实现和有超时的 Windows 测试实例，注入只有按下的 Pause，然后按 Esc 3.2 秒。得到 `phase=0, progress=0, held=2`：界面能收到 Esc，计时仍被 Pause 挡住。补发 Pause 松开后，Esc 可以正常退出。这复现了与反馈一致的失效路径，并不能确定孩子当时按过的具体键。

另一个实测约束：全局钩子拦截 A、左右修饰键等按下后，`GetAsyncKeyState` 仍返回未按下，而软件正确持有该键。因此不使用此 API 在保护中重置全部键位，以免把真正同时按着的键误清除。

## 修正

- Pause、Break、Unicode 文本包作为瞬时动作，不留下等待松开的持有记录。它们在 Esc 计时中触发时仍会取消本次计时。
- 忽略键盘溢出标记和 Print Screen 的伪扩展 Shift，保留真实 Shift 持有状态。
- 归一驱动扫描码前缀和修饰键别名；相同键的重复按下不产生第二份持有记录。
- 松开时优先匹配该键，再使用相同虚拟键和左右标记恢复扫描码不一致的记录；保留主回车和小键盘回车的区分。
- 修正启动时交换左右鼠标键的状态映射。Esc 被其他真实按键打断时增加“先全部松手”提示。
- 保留三秒时长、启动时已按住 Esc 的保护、多键取消及满时后等待全部松开的规则。

## 验证

新增核心回归覆盖只按不放的瞬时键、溢出标记、合成 Shift、扫描码与别名不一致、重复记录和双回车区分；10 万轮混合输入累计模拟约 5.6 小时后验证 Esc 退出。

新增 Windows 原生回归覆盖 make-only Pause、异常松开扫描码、真正按住另一键仍阻止退出，以及 1500 轮混合输入后的退出与输入不穿透。所有实例有 12～45 秒的独立超时；最终发布 EXE 的完整结果见 [验证记录](../VERIFICATION.md)。
