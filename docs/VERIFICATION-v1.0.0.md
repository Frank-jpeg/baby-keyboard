# v1.0.0 验证记录

本机环境：Windows 11 专业版 x64（10.0.26200），一块 2560 × 1440 显示器，4 个系统音频输出设备。开发使用 .NET SDK 10.0.400，分发包内含 .NET 10.0.11 运行组件。

## 已通过

- 编译：0 警告、0 错误。
- 18 项核心测试：长按阈值、主/小键盘回车、自动重复、短按不累计、多键及鼠标取消、启动时已有按键按住、退出等待全部松开、10 万次随机状态转换、字符映射、音量/波形连续性、音效限流。
- 9 项 Windows 原生集成测试：真实低级钩子阻止标记输入传播；Win、Alt+Tab、Alt+F4、鼠标按钮及滚轮；350 次连续按键；前台切换后的鼠标范围恢复；最终回车不穿透；启动时按住回车；音频故障；界面和输入线程卡死；强杀进程；部分钩子安装失败；独立测试超时；模拟 Windows 锁屏通知。
- 1 项实际音频设备测试：打开 PCM 输出，播放三段柔和提示音，驱动持续接受缓冲。
- 以上共 28 项检查通过。集成测试针对最终单文件 EXE 运行，启动子进程时移除了开发用的 DOTNET_ROOT 等环境变量；本机系统安装的运行时只有 .NET 6 和 .NET 8，验证了 EXE 不依赖系统安装 .NET 10。
- 1440 × 900 预览已目视检查；150% 渲染输出为 2160 × 1350，布局与文字完整。
- 测试结束后主进程、看护进程和测试窗口均已退出，键鼠正常，光标限制恢复。

原生测试有最多 45 秒的独立期限，并使用无编辑功能的专用窗口作为输入目标。观察钩子只统计测试标记事件，未记录用户按键。

## 修复过的实际问题

Windows 切换前台窗口时会清除原进程的光标范围限制。现在保护模式每 100 毫秒检查并恢复范围，期间鼠标按钮和滚轮始终由独立钩子拦截。修复后再次通过全部原生测试。

## 验证范围

多屏覆盖及不同 DPI 布局已有实现；由于本机只有一块显示器，未在实体多显示器上验收。150% 检查是离屏渲染验证，没有修改用户的系统缩放设置。锁屏路径验证使用模拟的 Windows 会话通知，没有实际锁住用户电脑。电源键、系统安全桌面、特殊 Fn 键和系统级触控板手势不在普通软件可保证拦截的范围内。
